## Goal

Ship 0.2.2 with both known defects fixed, so later work starts from a clean
slate rather than carrying a backlog attached to the previous line of work.

1. **Two README links 404 on the PyPI project page.** `readme = "README.md"`
   (`pyproject.toml:9`) makes the README the long description, and relative
   links do not resolve there. `README.md:448` (`CHANGELOG.md`) and
   `README.md:467` (`LICENSE`) are the last two — the same class of bug already
   fixed for the JSONL doc links at `README.md:175` and `291`.
2. **The unconfigured-fallback warning lies.** It says "which will create
   `<path>`" on every run, including runs that merely reuse an existing file.
   Recorded in `TODO.md` under "Defaults and messages".

Fixing (2) also fixes a defect not recorded anywhere: the warning fires at
`config.py:146`, *before* the backend class is resolved and before
`ensure_schema()` runs, so it also fires when either raises — announcing a file
that never gets created.

## Assumptions

- A changed log message is not a caller-facing break, so this is a patch bump
  under plan 005 step 2. Nothing a caller imports, calls or configures behaves
  differently.

## Steps

1. **Fix the two README links** (`README.md:448, 467`) to
   `https://github.com/latingate/eventlog-pro/blob/main/<path>`, matching the
   convention at `README.md:175`/`291` and `pyproject.toml:56`. Use `blob/main/`
   rather than a tag so they survive across releases.

2. **Split the warning function** in `src/eventlog_pro/config.py`, because
   existence must be sampled *before* anything opens the file and reported
   *after*:

   - `_default_dsn_target(settings, parsed) -> Path | None` — path derivation
     plus the three existing guards (`_warned_default_dsn`,
     `dsn_source != "default"`, `settings.backend`). Returns `None` when there
     is nothing to warn about, so a configured path never gets an extra
     `stat()`. Keeps deriving from `DEFAULT_DSN`, so the file named is the file
     opened.
   - `_warn_default_dsn(settings, target, *, existed)` — emits, sets the latch,
     and keeps the legacy `events.db` block after the main warning, unchanged.

3. **Move the call in `get_backend()`.** Sample `target.exists()` where line 146
   is now; emit after the `try/except` around `ensure_schema()` succeeds. **The
   latch moves into the emit function** — today it is set before the schema
   attempt, so a failed attempt would leave a retry silently un-warned.

4. **Three truthful message states**, sharing one prefix and one call-to-action
   so `eventlog-pro.db` and `EVENTLOG_DSN` stay substrings of all three:

   | State | Clause |
   |---|---|
   | Existed before | `is using the existing %s` |
   | Did not exist, does now | `created %s` |
   | Still absent — `auto_create_table=False`, deferred to the first write | `will create %s` |

   `created` is a substring of only the second (`will create` does not contain
   it), which gives the tests a clean discriminator. Keep the path a lazy `%s`
   argument, and do not re-`resolve()` inside the emit function.

5. **Fix the stale cross-reference** at `config.py:33`, which names
   `_warn_if_default_dsn`.

6. **Update the four existing tests** in `tests/test_config.py`: `105-117`
   passes as-is but gets tightened (rename to `..._naming_the_file_it_created`,
   assert `created` present and `will create` absent); `120-126`, `129-143` and
   `146-151` are unchanged, the last two because the legacy block keeps its
   position and `messages[1]` still resolves.

7. **Add three tests** for what has no coverage today:
   `test_a_second_run_says_it_is_reusing_the_file` (the regression test for the
   actual bug), `test_a_deferred_file_is_not_claimed_as_created`
   (`auto_create_table=False`), and
   `test_no_warning_when_the_schema_attempt_fails_and_a_retry_still_warns`
   (pins the latch fix).

8. **Update the documentation of the warning**: `gs_tests/check_event_log.py:9-21`
   (which quotes the message verbatim and documents the defect as a known rough
   edge), `docs/features/configuration.md:97-100`, and `README.md:315-316`.
   Delete the `TODO.md:112-125` bullet and its now-empty
   `## Defaults and messages` heading.

9. **Release 0.2.2** per plan 005: bump `__about__.py`; add `CHANGELOG.md`
   entries under `[Unreleased]`, rename to `## [0.2.2] - 2026-08-16`, add a
   fresh `[Unreleased]` carrying the HTML reminder comment, and update the link
   refs at `CHANGELOG.md:206-209`; branch, PR, green CI, squash merge; confirm
   CI green on the merge commit; tag `v0.2.2` and push it.

## Risks

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| A downstream log matcher depends on the old wording | low | low | only `tests/test_config.py` consumes the text; Django mode suppresses the warning entirely; the changelog calls it out under Fixed |
| The three-state logic picks the wrong branch on Windows path normalisation | low | medium | both `exists()` calls go through one `Path` object; never re-`resolve()` in the emit function |
| Losing the "not configured" hint when the schema attempt fails | medium | low | accepted deliberately — `BackendError` already names the path, and restoring it means a fourth wording branch doubling the noise on an already-fatal path |
| Reordering breaks the `messages[1]` indexing in the legacy test | low | low | the legacy block keeps its position inside the emit function |
| Two processes starting together both report "created" | low | low | sampling is not locked across processes; harmless for a warning |
| The warning is suppressed if `get_backend_class()` raises | low | low | unreachable while `dsn_source == "default"`, since the default scheme is always `sqlite`; theoretical only |

## Rollback

- **Before the tag:** revert the commit; nothing outside the repository changed.
- **Before the upload:** delete and re-push the tag (plan 005's Rollback).
- **After the upload:** the version is permanent. The warning change is cosmetic
  and non-breaking, so fixing forward with 0.2.3 is preferable to yanking. A
  consumer needing the old behaviour can pin `eventlog-pro==0.2.1`.
